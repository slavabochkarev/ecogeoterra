## Архитектура адаптера

`app/nspd.py` не зависит от интерфейса, OSM, классификации или модели исследования. Закреплённый `pynspd==1.1.15` предоставляет протокол HTTPS-запросов/ошибок `Nspd.request` и определения слоёв. Собственный `NspdGateway` формирует ограниченные запросы и проверяет сырые коллекции, прежде чем какая-либо сторонняя модель преобразует и потеряет исходную CRS. Готовый сторонний парсер не форкался.

Методы `Nspd.find`, `_search` и рекурсивный `search_in_contour_iter` не используются: первый может выбрать один результат, второй преобразует HTTP 404 в отсутствие объекта, последний способен выполнять много запросов. Ошибки HTTP здесь сохраняют свой смысл. Контракт тела `intersects` взят из исследованной версии [pynspd](https://github.com/yazmolod/pynspd/blob/e9019a7e26d12170c354c367cf1508cb6d317d57/src/pynspd/_sync/api.py). Это наблюдаемый клиентский контракт, не официальная гарантия НСПД.

`SecureNspd` переопределяет только построение HTTPX-клиента: `ssl.create_default_context()`, обязательный `CERT_REQUIRED`, проверка имени сервера, без ослабления набора шифров. Штатный небезопасный `pynspd.client.SSL_CONTEXT` не используется нашим транспортом. Эффективный SSL-контекст транспортного пула проверен тестом, отказ проверки сертификата воспроизведён реальным запросом. Нет скрытых повторов транспорта/декораторов, DNS-подмены, автоматических прокси, CAPTCHA или переключения на небезопасное соединение. Настройки `PYNSPD_*` не могут включить такой режим.

`app/cadastre.py` отвечает за входную модель, проверку геометрии, пространственное сравнение, нормализацию характеристик, сериализацию запросов и файловый кеш. Существующий FastAPI вызывает его из синхронного маршрута в рабочем потоке; обработчик не блокирует цикл событий. Для гарантии одного запроса на процесс приложение запускается с **одним worker**, как и прежде.

## Способы поиска: реализация и подтверждение

| Вход | Реализованный запрос | Проверено |
|---|---|---|
| Polygon/MultiPolygon | Один `POST /api/geoportal/v1/intersects?typeIntersect=fullObject`, полный контур с отверстиями в EPSG:4326; категории 36368, 36369, 36383, 36384 | Тело, слои, отверстия и сопоставление проверены фиктивными ответами. Живой запрос остановлен TLS; поддержка конкретных категорий сервером не подтверждена |
| Point / только координаты | WMS `GetFeatureInfo` четырёх слоёв, максимум четыре последовательных запроса без повторов; до восьми при временных сбоях | Параметры, порядок осей и проверка покрытия проверены фиктивными ответами. Живой WMS не запускался после установленной TLS-проблемы |
| Кадастровый номер | `NspdGateway.by_number`, `GET /api/geoportal/v2/search/geoportal?query=…&thematicSearchId=1` | Контрольный живой запрос остановлен TLS. Не подменяет пространственный поиск, доступен для явной диагностики |
| LineString/MultiLineString OSM | Возвращается `unavailable / unsupported_geometry` | Протестировано; центр или буфер не подставляется |

Слои и категории — разные идентификаторы: участки **36048 / 36368**, здания **36049 / 36369**, сооружения **36328 / 36383**, ОНС **36329 / 36384**. Для WMS 1.3.0 с EPSG:4326 BBOX передаётся в порядке **south, west, north, east** (latitude/longitude); координаты GeoJSON и API приложения всегда longitude/latitude. После WMS каждый кандидат проверяется реальной геометрией, чтобы не принять соседний объект из-за пиксельного допуска. При достижении лимита 10 объектов хотя бы в одном слое выдача считается потенциально неполной и не кешируется как успех.

Если сервер отвергнет маршрут, категорию или формат, пользователь увидит `unavailable`, а не имитацию совпадения или «не найдено». Без доверенного TLS-канала невозможно определить, поддерживается ли запрос сервером в настоящий момент. После настройки доверия нужно повторить ограниченный тест. Альтернатива при недоступном пространственном API — вручную установить кадастровый номер по официальной карте и выполнить отдельный поиск по номеру, сохраняя его как независимый результат; ввод номера в интерфейсе этой версии не добавлялся.

## Геометрия и основания сопоставления

Входной GeoJSON без `crs` трактуется согласно его соглашению как WGS84. Явная именованная CRS проверяется через pyproj; преобразование выполняется с `always_xy=True`. CRS из ответа НСПД читается на геометрии, feature или коллекции. Исходная CRS сохраняется в `source_crs`; возвращаемая геометрия — EPSG:4326 без устаревшего поля `crs`. Проверяются конечность координат, диапазоны, непустота и валидность Shapely. Самопересечения не исправляются молча; невалидный OSM-вход даёт 422, испорченный ответ НСПД — `error`.

Для полигонов рассчитываются площадь пересечения, доля площади OSM и доля площади кандидата в локальной метрической AEQD, центрированной на исходной геометрии. Фиксированная UTM-зона не применяется. Кандидаты с положительной площадью пересечения сохраняются, даже если пересечение мало; порог «50% значит принадлежит» отсутствует. Чистое касание границ без площади не считается совпадением полигонов. Для точки проверяется `candidate_geometry.covers(osm_point)`.

Кандидат без геометрии остаётся непроверенным. Если вместо контура кадастрового объекта дана точка/линия, пересекающая полигон OSM, кандидат тоже сохраняется с предупреждением и без вычисленной доли площади. Даже единственный такой кандидат требует ручного выбора: `multiple_matches`, `selected_candidate=null`. При нескольких кандидатах всегда требуется выбор; первый автоматически не назначается. При одном проверенном пространственном результате `matched` означает геометрическое совпадение, а не юридическое тождество.

ВРИ и категория земель выводятся **только в карточке участка**. Назначение, имя, этажность и год постройки — в карточке ОКС. Эти характеристики не превращаются в фактическую деятельность организации. Исходные дополнительные поля и геометрия доступны в раскрываемом блоке. Отсутствующее поле — «Нет данных»; нулевые значения сохраняются.

## API

`POST /api/cadastre/enrich`, JSON, без автоматических запросов на выбор объекта:

```json
{
  "osm_type": "way",
  "osm_id": 135674075,
  "geometry": null,
  "coordinates": [49.279, 53.558],
  "tags": {"building": "yes"}
}
```

Этот пример демонстрирует **поиск только точки**; координаты условные. Интерфейс передаёт полную имеющуюся геометрию выбранного объекта. Отсутствие обоих способов задания положения или невалидная геометрия даёт HTTP 422 без обращения к НСПД. При наличии геометрии она имеет приоритет; неверный контур не заменяется переданными координатами.

Поля ответа: `status`, `source="NSPD"`, `retrieved_at` (UTC ISO 8601 либо null), `cache_hit`, `candidates`, `selected_candidate` (ID либо null), `warnings`, `search_method`, `error_code`, `message`. Каждый кандидат содержит `id`, `cadastral_number`, `category_id`, `object_type`, `characteristics`, `raw_options`, `geometry`, `geometry_crs`, `source_crs`, `match_basis`, `spatial_relation`, `intersection`.

| Статус | Смысл |
|---|---|
| `matched` | Один проверенный пространственный кандидат |
| `multiple_matches` | Несколько кандидатов либо требуется ручная проверка неполного контура |
| `not_found` | Только корректная полная пустая выдача или отсутствие пересечения после локальной проверки |
| `unavailable` | HTTP/TLS/соединение, лимит, занятый адаптер, неподдерживаемая геометрия |
| `error` | Некорректные характеристики, геометрия или CRS ответа |

Для этих результатов маршрут возвращает HTTP 200 со статусом в теле. HTTP 403/404/429 НСПД не преобразуются в успешный пустой результат. На 403 нет автоматического повтора. На 429 используется `Retry-After` в секундах, ограниченный 1–3600 с; для нечислового/отсутствующего заголовка — 60 с. До окончания паузы новые запросы отклоняются локально. Временные ошибки соединения, тайм-ауты и 5xx допускают **один повтор** с паузой 0,5 с; после TLS-ошибки повтора нет. Полнота проверяется по обнаруживаемым признакам `partial/truncated/hasMore/next`, ошибкам и счётчикам коллекции. Неполный или не-JSON ответ не означает отсутствия объекта.

## Кеш и настройки

Кеш по умолчанию: `.cache/NSPD/`; при desktop-запуске используется общий существующий механизм пути кеша. Ключ SHA-256 включает версию схемы запросов/параметров, URL, набор категорий, `osm_type/id`, нормализованную геометрию/координаты и исходные теги. Изменение геометрии меняет ключ. TTL — 86400 с. Запись атомарная; испорченный или просроченный файл игнорируется. Сохраняются только завершённые `matched/multiple_matches/not_found`. Ошибки доступа и TLS не записываются. Недоступный кеш не препятствует показу полученного ответа, добавляется предупреждение.

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `NSPD_CACHE_TTL_SECONDS` | `86400` | TTL, `0` отключает повторное использование |
| `NSPD_TIMEOUT_SECONDS` | `12` | Тайм-аут отдельной сетевой операции, connect не более 5 с; это не общий тайм-аут всех четырёх WMS-слоёв |
| `NSPD_CA_FILE` | не задана | PEM-файл дополнительных доверенных CA, добавляемый к системным |
| `CACHE_DIR` | существующее значение проекта | Корневая папка кеша, внутри создаётся `NSPD` |

Если у вас есть проверенный доверенный CA для НСПД/вашей сети, явно задайте путь перед запуском:

```powershell
$env:NSPD_CA_FILE = 'C:\Certificates\trusted-ca.pem'
powershell -ExecutionPolicy Bypass -File .\start.ps1 -Port 8001
```

Файл не скачивается и не устанавливается автоматически. Если доверие по-прежнему не устанавливается, исправлять нужно цепочку сертификатов/сеть; небезопасного переключателя в адаптере нет.

## Визуальная проверка

Браузерная проверка использовала отдельный временный сервер с сохранённым реальным OSM-ответом, явно обозначенным в строке состояния. На первом стенде НСПД запрашивалась **вживую**: появился индикатор, карта и «Исследовать» оставались доступными, затем отображена TLS-ошибка.

На втором временном стенде использовались архивный ответ поиска участка по номеру из `NSPD-Research/evidence/http-search-response.json` и явно фиктивный ОКС `ТЕСТ:ОКС`. В строке состояния есть пометка **«ПРОВЕРКА UI»**. Это проверка отображения, не живой результат пространственного API и не подтверждение соответствия ОКС. Дата «Получено» на этом тестовом стенде относится к прогону фикстуры.

В браузере подтверждены: два кандидата без автоматического выбора первого; ручной выбор участка и ОКС; поля участка и «Нет данных» у ОКС; получение из кеша; смена выбранного OSM-объекта во время задержанного запроса; блокировка второго запроса без блокировки карты; отсутствие подстановки ответа предыдущего объекта в карточку нового; отсутствие ошибок JavaScript в журнале. ## Известные ограничения

- Для реальных данных в текущей среде требуется решить доверие TLS. Успешный живой поиск по контуру, точке и контрольному номеру этой реализацией пока не подтверждён.
- Маршруты и ID категорий основаны на исследованном клиенте pynspd и могут измениться; нет официальной гарантии полноты выдачи. Проверяются только наблюдаемые признаки неполноты.
- WMS имеет лимит 10 на слой; поиск не расширяется, не сканируется и не разбивается рекурсивно. Контуры больше 10 км² отклоняются. Линейные OSM-объекты не поддерживаются на входе.
- GeoJSON без CRS допустим как WGS84; невозможно определить ошибочно подписанную CRS, если значения при этом выглядят правдоподобно.
- Автоматического подтверждения юридического соответствия нет. Единственный участок под OSM-зданием остаётся отдельным участком; ВРИ не переносится зданию.
- В кеш/память UI не добавлены серверное хранение пользовательского выбора и ручное редактирование данных. Выбор кандидата хранится в карточке текущего сеанса.
- Нет отдельного общего тайм-аута на всю группу WMS-запросов, есть ограниченное число вызовов и тайм-аут каждой сетевой операции. Пауза `Retry-After` в HTTP-date трактуется как стандартные 60 с.
- Адаптер должен работать с одним Uvicorn worker. Серверная блокировка и пауза действуют в пределах одного процесса, не между независимо запущенными копиями приложения.
- ОКС/участки без опубликованной геометрии нельзя достоверно найти только пространственным запросом. Кандидаты без контура требуют проверки; отсутствующие данные не восстанавливаются предположениями.
