# CR-008.1 · Стабилизация Map First

20.11.2026 · [Руководство запуска](../architecture/08_DEPLOYMENT.md) · [Контракты API](../architecture/04_API_REFERENCE.md)

## Причина ошибки сохранения

Долгоживущий сервер на 8000 загружал Python и строгую схему `WorkingState` при старте. Маршруты HTML и `StaticFiles` в это же время читали исходные файлы при каждом запросе. После обновления файлов браузер получал Map First с вкладкой ООПТ, а запущенный сервер сохранял прежнюю схему. Его OpenAPI не содержал `POST /api/oopt/research`.

Клиент собирает `snapshot()` и передаёт его в `PUT /api/researches/{research_id}` как `state` вместе с ревизией. В актуальном состоянии `state.oopt_anchor` присутствует даже со значением `null`. Прежняя схема отклоняла это поле как неизвестное. Для открытой вкладки ООПТ прежняя схема также отклоняла `state.tab = "oopt"`. Ошибка 422 возникала до обращения к JSON-хранилищу. Обе причины воспроизведены на прежней схеме. Актуальная схема принимает это состояние и поддерживает ранее сохранённые манифесты без новых полей.

## Исправление и TD-07

- При старте backend делает временную копию статики из того же дерева проекта. `/`, `/map` и `/static` используют её до остановки процесса. Ответы HTML и ресурсов содержат `Cache-Control: no-store`.
- Строгая валидация сохранена. Ответ 422 содержит путь к первому отклонённому полю и безопасное описание ошибки. Значения полей в ответе об ошибке опускаются.
- «Повторить сохранение» собирает текущее состояние страницы. Ревизия меняется после подтверждения сервера. При 409 показано указание обновить страницу, а устаревший запрос отклоняется без перезаписи. Ошибка открытия повреждённого файла видна пользователю, файл остаётся доступен для диагностики.
- TD-07 закрыт проверкой двух запусков на временной копии проекта. После изменения HTML, JS и CSS первый процесс продолжил выдавать исходные байты. Новый процесс выдал обновлённые файлы. На рабочем 8000 подтверждены актуальный API ООПТ и загрузка ресурсов.

Порядок обновления — сохранить работу, остановить свой экземпляр, обновить файлы, выполнить `.\start.ps1 -NoBrowser` и обновить уже открытые вкладки. Исследования по-прежнему хранятся в `data/researches` или в заданном `RESEARCHES_DIR`.

## Уведомления и радиусы

Постоянная плашка «На карте» убрана. Успешные действия в кадастровом сценарии и изменение радиуса используют одно уведомление на пять секунд. Следующее сообщение заменяет текущее и перезапускает таймер. Перерисовка карты и восстановление сохранённого исследования уведомлений не создают. Ошибки и предупреждения, требующие действий, остаются видимыми. Подтверждённый радиус отображается в сведениях о результате и отчётах, выбранный радиус — в селекторе.

На 8000 доступны 500 и 1000 м. Радиус 2000 м использует прежний серверный флаг. Его допуск проверен с флагом в изолированном запуске. Алгоритм буфера, серверные лимиты, хранение выборки и форматы отчётов сохраняют действующие контракты.

## Выведенные из эксплуатации страницы

Для `/legacy/osm`, `/legacy/cadastre-experiment` и `/cadastre-experiment` сервер возвращает 404. Из `app/static` удалены `index.html`, `app.js`, `styles.css`, `cadastre-experiment.html`, `cadastre-experiment.css` и `cadastre-experiment.js`.

Публичные `POST /api/cadastre/enrich` и `POST /api/cadastre-experiment/research` сохранены для совместимости и отмечены как deprecated в OpenAPI. Map First использует `POST /api/cadastre/research` для исследования и сохраняет вызовы `/api/cadastre-experiment/source` и `/api/cadastre-experiment/basemaps`. Leaflet, адаптер Esri и общие модули остались доступны.

### Сохранность исследований

До тестов сделана локальная резервная копия четырёх исследований. Все 13 SHA-256 совпали с контрольными суммами протокола. Записывающие проверки выполнялись в отдельном каталоге. На рабочем экземпляре проверки исследований выполнялись через GET.

После запуска прочитаны четыре исходных и одно добавленное исследование. Все ранее существовавшие файлы кадастровых и OSM-выборок совпали с копией. В рабочем каталоге изменились указатель активного исследования и один прежний манифест (камера, поисковый ввод, выбор участка, привязка ООПТ, ревизия и время сохранения). Рабочие файлы оставлены в текущем состоянии. Резервная копия сохранила первоначальные байты.

### Границы проверки

Геоданные и тайлы для браузерной проверки поставлялись локальными фикстурами. Живая проверка провайдеров и подтверждение полноты НСПД на 2000 м в этот этап не входили. Установка из готового Windows-архива отдельно не проверялась. Для открытой вкладки после перезапуска требуется обновление страницы. При конфликте ревизий перед обновлением стоит выписать несохранённые изменения, которые нужно внести повторно.
