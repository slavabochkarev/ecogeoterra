# CR-011 — Исследование зон и поиск ООПТ

**20 ноября 2026 года.** В Map First появилась вкладка «Исследование» между «Объекты» и «Координаты». Она выполняет поиск ООПТ вокруг опорной точки выбранного объекта. Поддерживаемые диаметры 10, 40, 100 и 200 км дают радиусы 5, 20, 50 и 100 км. По умолчанию выбран диаметр 40 км.

## Архитектурное решение

Панель вкладок реализована в `interface.js`, существующая карта работает на Leaflet. Источник кадастра и выделенный участок хранятся в кадастровом контроллере. Объект OSM хранится в контроллере OSM, а адрес, координаты поиска и выбранная точка — в контроллерах поиска и координат. Новая вкладка получает события выбора от этих контроллеров. Для кадастрового полигона используется существующая `label_point`. Для объекта OSM используется его точка или ранее рассчитанная ближайшая точка геометрии. Координаты поискового ориентира берутся из существующего поиска. При отсутствии опорной точки интерфейс объясняет, почему поиск недоступен.

Отдельный SVG строится в браузере из геометрий ответа. На вкладке отображаются круг текущего радиуса, направления, сетка и контуры, обрезанные по кругу. Выбор строки или контура выделяет одну и ту же зону. Из списка доступны номера, полученные названия, расстояния и попадание внутрь. Точки на контурах помогают выбирать малые зоны. Геометрия Leaflet и поведение других вкладок сохраняются.

`POST /api/oopt/research` строит в AEQD полигон из 360 вершин и передаёт его в EPSG:4326 в `NspdGateway.search_oopt`. Шлюз использует `SecureNspd` и существующий ограниченный POST `/api/geoportal/v1/intersects?typeIntersect=fullObject` с категорией `472825`. Запросы выполняются с общей блокировкой и трёхсекундной паузой НСПД, без автоматических повторов. Пауза поставщика на HTTP 429 учитывается через `Retry-After`. Дедлайн обработки 35 с, предел ответа 16 МиБ и 250 000 исходных координатных позиций. Единственный запрос посылается по полигону, включая вариант с пересечением антимеридиана.

Номера извлекаются из `options.reg_numb_border`. Повтор одного номера с совпадающим контуром сводится к одной записи. Невалидные записи и несовместимые контуры одного номера дают предупреждение о частичной выборке. Контуры EPSG:3857 проецируются в AEQD. При попадании точки внутрь расстояние до территории равно нулю и отдельно выдаётся расстояние до границы. Для карты контуры обрезаются и упрощаются с допуском 1 м. Измерения выполняются до обрезания и упрощения. Протоколы GEO‑RD‑007–010 хранятся локально. [Справочник API](../architecture/04_API_REFERENCE.md)

Уменьшение диаметра для той же точки может использовать уже загруженную выборку. Выбор и подпись радиуса обновляются, повторного запроса не происходит. При смене объекта прежние данные удаляются, запоздавший результат игнорируется. Сохранённые исследования получают необязательное поле `oopt_anchor` для восстановления существующего выбора. Сама выборка ООПТ остаётся в памяти вкладки браузера. [Модель состояния](../architecture/05_DATA_MODEL.md)

## Ограничения и следующая версия

Результаты предназначены для предварительного обследования. Полнота выдачи и юридическая актуальность границ не подтверждены, в том числе при пустой выдаче. Интеграция использует только ООПТ. Сохранение результатов ООПТ, экспорт отчёта, другие виды зон и расстояние от границы земельного участка остаются за рамками CR‑011.

Проверки выполнены в отдельном процессе с временным хранилищем. Запущенный ранее экземпляр на `127.0.0.1:8000` продолжает обслуживать старый набор маршрутов. Обновление загружается при штатном перезапуске GEO. Архив Windows не пересобирался.
