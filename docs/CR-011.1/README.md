# CR-011.1 — Названия и подробная карточка ООПТ

Вкладка «Исследование» показывает название, когда его вернула НСПД. Для выбранной зоны можно открыть карточку кнопкой «Подробнее» и вернуться к списку. Карта продолжает выделять выбранный контур. Сортировка остаётся по расстоянию, фильтр работает по реестровому номеру.

## Что возвращает НСПД

20 ноября 2026 года проверены 189 записей из локальных протоколов GEO‑RD‑007–010 и выполнены четыре поисковых GET через `SecureNspd` с проверкой TLS. По каждому контрольному номеру проверены поиск в слое `875845` и режим `thematicSearchId=5` («Зоны и территории»). Дополнительно изучены схема `pynspd==1.1.15` и публичная статика портала. [Выпуск pynspd](https://pypi.org/project/pynspd/1.1.15/)

| `63:00-9.2` | HTTP 200, 1 запись категории 472825 | HTTP 200, 2 записи, категории 472825 и 36948 | Название по документу содержит «Национальный парк „Самарская Лука“». Регистрация 27.12.2021. Приказ Минприроды России от 25.02.2015 № 69. |

Пространственная выдача категории `472825` содержит `options.reg_numb_border`, контур и служебные свойства. В обеих контрольных записях `label`, `descr` и `externalKey` повторяют номер. В сохранённых пространственных ответах единственное поле `options` — `reg_numb_border`. Название и реквизиты даёт дополнительная запись категории `36948`. У двух контрольных номеров её геометрия совпала с геометрией категории `472825`. В приложении карта и расстояния продолжают использовать исходный пространственный результат. [Ответ по Самарской Луке](https://nspd.gov.ru/api/geoportal/v2/search/geoportal?query=63%3A00-9.2&thematicSearchId=5) · [Ответ по Ставропольскому сосняку](https://nspd.gov.ru/api/geoportal/v2/search/geoportal?query=63%3A09-6.96&thematicSearchId=5)

## Поля карточки и их источники

| Поле | Источник и проверка |
|---|---|
| Название | `options.name_by_doc` в записи 36948. Из пространственного ответа принимаются явные `name_by_doc` и `name`, когда они есть. Номер и технические подписи не выдаются за название. |
| Реестровый номер | `options.reg_numb_border`. Дополнительная запись должна точно совпадать с выбранным номером. |
| Вид ООПТ | `options.type_zone` пуст в обеих контрольных записях, поэтому отображается «Нет данных». Специализация есть в самом названии по документу. Её не выделяем в отдельный вид по тексту. |
| Вид объекта реестра | `options.type_boundary_value` содержит «Особо охраняемая природная территория» или «Граница особо охраняемой природной территории». `categoryName` показывается отдельно как название слоя. |
| Местоположение и площадь | Подтверждённых полей в этих ответах нет. Карточка показывает «Нет данных». Кадастровый код вынесен в отдельное поле. |
| Кадастровый код | `options.cadastral_district` в режиме «Зоны и территории», `properties.cadastralDistrictsCode` в пространственном ответе. |
| Дата регистрации и документ | `registration_date` и поля `legal_act_document_name`, `legal_act_document_number`, `legal_act_document_date`, `legal_act_document_issuer` внутри `options`. Даты документа и регистрации показаны отдельно. |
| Другие характеристики | `options.old_account_number` и `options.content_restrict_encumbrances`. Режим охраны можно раскрыть в карточке. |
| Дата и источник сведений | `systemInfo.updated` — дата обновления технической записи НСПД. Отдельно показаны дата получения ответа и режим запроса. |
| Расстояние | Из действующего результата CR‑011. При попадании точки внутрь отдельно показано расстояние до границы. |

## Изменения

Локальный `GET /api/oopt/details?number=…` вызывает тематический поиск через проверяемый TLS и общие блокировку и паузу НСПД. Возвращает только атрибуты записи 36948 с точным совпадением номера. Учитываются HTTP 429 и `Retry-After`. При отсутствии точной дополнительной записи карточка показывает сообщение и доступные поля пространственного ответа. Ошибки показываются в карточке, повтор запускается кнопкой.

Запрос выполняется по действию «Подробнее», если записи ещё нет в памяти и нужные сведения отсутствуют в пространственном ответе. Выбор строки, открытие списка, фильтр и перерисовка не вызывают запрос деталей. Полученное название появляется в списке сразу после загрузки. Повторное открытие использует результат из памяти текущей страницы.

- API и извлечение атрибутов — [main.py](../../app/main.py), [nspd.py](../../app/nspd.py), [oopt.py](../../app/oopt.py).

## Проверки и ограничения

86 тестов прошли. Проверены точная привязка по реестровому номеру, извлечение названия и дат, отсутствие названия и дополнительной записи, обработка 429 и сохранение сценариев CR‑011. Тесты CR‑008.1 проверили совместимость состояния и конфликт ревизий, выдачу Map First и отсутствие удалённых страниц. Схема сохранения, снимок статики, кадастровые уведомления и настройки радиусов CR‑008.1 сохранены. [Исходный CR‑011](../CR-011/README.md) · [CR‑008.1](../CR-008/README.md)

В Edge проверены 1400 × 900 и 390 × 844, оба контрольных номера на сохранённых ответах НСПД, выделение того же контура с тем же цветом, возврат к списку и сохранение сортировки. Для 123 найденных ООПТ при просмотре списка и выборе строки обращений за деталями не было. При явном открытии карточек проверены загрузка, пустая дополнительная выдача, 429 и повторное открытие из кеша. Меньшие радиусы по-прежнему использовали имеющуюся выборку. В изолированном хранилище открыто сохранённое исследование с вкладкой ООПТ. Изменённый JS появился после перезапуска тестового процесса, до него действовал снимок с `Cache-Control: no-store`.

Сведения имеют справочный характер. Полнота выдачи и юридическая актуальность границ остаются неподтверждёнными. Список может показывать реестровый номер до первого просмотра карточки. Карточка и её кеш не записываются в сохранённое исследование.
