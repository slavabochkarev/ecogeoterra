# CR-006 · Архитектура

## Границы и внедрение

Один FastAPI раздаёт статические ресурсы и одно основное рабочее место с одним Leaflet. Оба старых HTML/CSS/JS сохраняются как независимые входы к тому же backend на время миграции. Новый экран предлагается на `/map`, после приёмки — на `/`, прежний v0.2 получает `/legacy/osm`, эксперимент сохраняет адрес. Самый обратимый вариант переключения — выбор страницы маршрутом/конфигурацией поставки. Frontend использует относительные к origin пути API. При публикации под URL-префиксом базовый путь статических ресурсов и API передаёт сервер. Контейнер в будущем содержит приложение и закреплённые зависимости, получает конфигурацию TLS/поставщиков в окружении и использует ограниченный том кеша. Публикуемый HTTPS origin, внутренний bind и порт независимы.

## Frontend

Оставить нативные ES-модули и локальные vendor-ресурсы. Новый entry point собирает модули, связывает обработчики и инициализирует карту один раз. Сначала извлечь адаптеры и чистые функции из проверенных реализаций, оставляя маршруты и загрузку старых скриптов самостоятельными. Компоненты ниже — зоны ответственности. Близкие функции могут находиться в одном небольшом модуле.

Черновой радиус, параметры запроса и параметры показанного результата — отдельные поля. Кадастровая заявка, запущенная для радиуса A, теряет право коммита при изменении черновика до ответа. Сохраняется последний принятый результат. При возврате на A через другой радиус нужен явный повтор или присоединение к ещё допустимой операции по ключу. OSM проверяет актуальность по нормализованным координатам и радиусу, сохраняет выбор при скрытии и заново связывает его по ID при восстановлении данных. Смена отображения, подложки или фильтра не инвалидирует выборку. [Опции Leaflet](https://leafletjs.com/reference#map-invalidatesize)

## Backend и контракты

Разделение по сервисам без второго процесса приложения. Поиск адреса и объекты продолжают использовать `services.py`, `classification.py`, `osm.py` и `MetricContext.measure`. Для кадастра переиспользуются `NspdGateway`, валидаторы, земельная нормализация, `land_collection` и `parcel_measurement`. Выделяется сервис подбора/территориальной выдачи с параметром радиуса и едиными ограничителями. Кеш и провайдер подложки — инфраструктура. Сохраняются TLS, логика AEQD, порядок координат, обработка колец и отсутствие автодробления области. Пропуски контуров, кеш и свежесть доступны сервису и UI. При адаптации legacy 500 м явные счётчики невалидных записей и контуров дают предупреждение о пропусках даже при исходном `coverage=unknown`.

| Метод/путь | Требование |
|---|---|
| Существующие `GET /api/geocode?q=…`, `GET /api/config`, `POST /api/research` | Без изменений. Новый клиент всегда отправляет явный radius и сохраняет метаданные точечного OSM-исследования. OSM вокруг точки и кадастр вокруг полного контура могут охватывать разные территории при одном числе метров. |
| Существующие `POST /api/cadastre/enrich`, `GET /api/cadastre-experiment/source`, `GET /api/cadastre-experiment/basemaps` | Переиспользовать без смены контракта. Конфигурация подложки запрашивается один раз на загрузку страницы. API Esri сохраняет no-store и режим same-origin. |
| Существующий `POST /api/cadastre-experiment/research` | Принимает только `{number}`, радиус 500 м. Старый контракт и namespace кеша сохранены. Map First использует этот маршрут как резерв для 500 м при недоступной конфигурации возможностей. |
| Новый `POST /api/cadastre/source-candidates` | Запрос `{lat,lon}` в десятичных WGS84, ограничения широты ±85°, долготы ±180°. Ответ `{point,candidates,retrieved_at,cache_hit,coverage,warnings}`. Кандидат содержит земельный номер, нормализованный parcel при наличии, адрес/категорию при наличии, статус геометрии и отношение `inside/boundary/near/unverified` с дистанцией для near. Возвращать в порядке inside, boundary, near по дистанции, unverified, затем номер. Никакого автоподтверждения. |
| `POST /api/cadastre/research` | `{number, radius_m, source_revision?}`. Радиус — число 500, 1000 или 2000, лишние поля отклоняются. При наличии ревизии клиент передаёт 64-символьный SHA-256. HTTP 200 возвращает `source`, `source_revision`, `buffer`, `parcels` без исходного, `stats`, `radius_m`, `retrieved_at`, `cache_hit`, `coverage`, `coverage_details` (`reason`, `confirmed`, `records_skipped`) и `warnings`. `buffer.properties.radius_m` равен фактическому радиусу. |
| `GET /api/cadastre/capabilities` | `{source_candidates, radii:[{radius_m,enabled,reason}]}`. Map First читает допуск один раз при загрузке. Отключённые варианты видимы, но недоступны. Сервер проверяет допуск до чтения кеша и до обращения к НСПД. |

Подбор по точке — новая функция. Предлагается один земельный POST с буфером 15 м от ориентира, после чего центральная точка проверяется `contains/covers` по возвращённым GeoJSON. Отдельный набор кандидатов, привязанный к координатам. Покрытие точки, касание границы и близлежащий участок различаются. Отсутствие валидного контура показывает причину и блокирует подтверждение. Нулевой подходящий результат с неизвестной полнотой предлагает номер или перемещение ориентира. Увеличение окна, WMS-резерв и автоматические повторные запросы не входят в базовый сценарий. Для исследования сервер принимает только номер, сам разрешает точный доверенный контур из кеша/поиска; подтверждённый ответ кандидатов допускается использовать как кеш исходного участка только после эквивалентной проверки идентичности и характеристик. Иначе применяется существующий точный lookup. Ориентир за пределом ±85° может использоваться для навигации по Web Mercator в прежних пределах, но поиск и OSM требуют допустимого ориентира.

Ревизия — хеш нормализованной WKB-геометрии исходного участка с номером. Смена ревизии даёт 409 `source_changed`. Перед первым исследованием исходный контур получен старым маршрутом или из подтверждённого кандидата. Если присланное GeoJSON-представление отличается от подтверждённого, браузер сохраняет прежние данные и предлагает снова найти исходный участок. После принятого результата клиент передаёт ревизию в следующих запросах. Изменение чернового радиуса не создаёт POST и исключает применение устаревшего ответа. На карте отдельно показан фактический радиус. Контуры подготавливаются в Leaflet порциями по 100 вне активной карты, затем набор меняется целиком. На карте отображается до 100 читаемых подписей, список открывает по 100 соседей.

## Безопасная загрузка НСПД

Исторические B1000/B2000 подтверждают единичные ответы. Полнота, квоты, максимумы и пагинация остаются неподтверждёнными. Новый маршрут отправляет один земельный `intersects` по буферу полного контура. При промахе кеша исходного участка сначала выполняется точный поиск по номеру. [Архивные данные](01_CURRENT_STATE.md#история-cr-и-полнота-нспд)

### Допуск радиусов

500 м разрешён всегда. `NSPD_RESEARCH_ENABLE_1000=1` и `NSPD_RESEARCH_ENABLE_2000=1` включают соответствующий радиус независимо после перезапуска backend. Значение `true` также принимается. В отсутствие переменной радиус выключен. На стенде с подменённым транспортом можно включить оба радиуса для фикстур. Настройки рабочего экземпляра включаются по отдельному согласованию для каждого радиуса.

После согласования, из корня проекта в PowerShell, запустите свой экземпляр с нужным флагом. Для 2000 м используйте отдельную переменную `NSPD_RESEARCH_ENABLE_2000`.

```powershell
$env:NSPD_RESEARCH_ENABLE_1000 = '1'
.\.venv\Scripts\python.exe -B -m uvicorn app.main:app --host 127.0.0.1 --port 8003 --workers 1
```

|---|---|

Одинаковые запросы с тем же номером, радиусом и ожидаемой ревизией разделяют одну операцию. До пяти разных ключей одновременно, включая активный. Ожидание lock до 10 с, затем 409. Для нескольких воркеров и реплик требуется общая координация. |

| Ответ | До 16 MiB потокового ответа до разбора JSON и до 16 MiB готовой сериализованной выдачи. Транспорт запрашивает `identity` и отклоняет неожиданное сжатие. До 5000 объектов и 250 000 координат до обработки; те же ограничения проверяются для готовой выборки. Превышение — 502. |
| Время и ошибки | Общий дедлайн публикации 35 с с момента входа, включая ожидание и обработку. HTTPX ограничивает connect 5 с и ввод-вывод 12 с либо оставшимся временем. Дедлайн проверяется на чтении и при обработке. Текущий синхронный вызов может удерживать слот до сетевого таймаута. При 429 учитываются числовой и HTTP-date `Retry-After`, резерв 60 с. Повторы, пагинация и дробление области отсутствуют. |
| Кеш | Новый каталог `research-v2` внутри кеша НСПД. Ключ включает версию схемы/алгоритма, endpoint, категорию, тип запроса, номер, радиус, ревизию и профиль лимитов. Контрольная сумма обнаруживает повреждение файла. При записи удаляются истёкшие, затем самые старые записи до соблюдения квоты 512 MiB. TTL наследуется от `NSPD_CACHE_TTL_SECONDS` (24 ч по умолчанию). Прежние файлы остаются в своих пространствах. |

Конфигурируемые предварительные лимиты приложения задаются положительными целыми переменными `NSPD_RESEARCH_MAX_AREA_KM2`, `NSPD_RESEARCH_MAX_REQUEST_VERTICES`, `NSPD_RESEARCH_MAX_REQUEST_BYTES`, `NSPD_RESEARCH_MAX_RESPONSE_BYTES`, `NSPD_RESEARCH_MAX_RESPONSE_VERTICES`, `NSPD_RESEARCH_MAX_OBJECTS`, `NSPD_RESEARCH_DEADLINE_SECONDS` и `NSPD_RESEARCH_CACHE_MAX_BYTES`. Эти значения описывают локальные бюджеты приложения. Старый маршрут 500 м сохраняет прежнюю политику.

### Полнота и сохранение результатов

| Статус | Значение |
|---|---|
| `complete` | Контракт и полнота подтверждены. Клиент поддерживает отображение. Текущий шлюз не выставляет этот статус, поскольку гарантия НСПД не подтверждена. |
| `unknown` | Ответ прошёл проверки, гарантия полноты отсутствует. Выборка может быть нанесена и сохранена в кеш со статусом. |
| `partial` | При локальных пропусках в пригодной выдаче возвращается HTTP 200 с предупреждениями, без записи в кеш. При явном усечении, следующей странице, расходящихся счётчиках или отсутствии проверенных контуров на фоне повреждённых записей возвращается HTTP 502 `incomplete_response` без новой геометрии. Предыдущая выборка остаётся на карте. |
| `failed` | Ошибка запроса или обработки, в том числе превышение бюджета, 429, 503 и дедлайн. Предыдущая выборка остаётся на карте. |

## Объекты OSM и отображение карты (4)

`osm.js` хранит отдельно последний принятый набор, параметры следующей загрузки, выбор и фильтры. Отправляются прежние `{lat,lon,radius,source_label}` в `POST /api/research`. Опора — выбранный адрес или координаты; после поиска по точному кадастровому номеру берётся `label_point` из серверного контура. При подтверждении кандидата у точки сохраняется опора поиска. Буфер и кадастровые расстояния в этот запрос не входят. `GET /api/config` поставляет девять категорий с прежними именами и цветами. Overpass по действующему контракту получает общий набор, выбор категорий и фильтр безымянных применяются на клиенте к карте, списку и экспорту.

Переключатель видимости снимает только Leaflet-группу. При новом запросе свежий ответ для той же точки (до семи десятичных знаков) и радиуса берётся из кеша в памяти, до пяти ключей и 24 ч по дате получения от backend. Старый ответ остаётся доступен в панели с собственными параметрами; при несовпадении он скрывается с карты. Запоздалый ответ сохраняется для ключа, с которым отправлялся. Таймаут, ошибка и скрытие группы сохраняют последний пригодный набор. Backend SHA и настройки Overpass остались прежними. [Публичный Overpass](https://dev.overpass-api.de/overpass-doc/en/preface/commons.html)

`osm-map.js` рисует группу OSM над Canvas кадастра, с собственной линией от опорной точки до ближайшей точки геометрии. Событие OSM проходит проверку попаданий Canvas для меню выбора слоя. `osm-panel.js` выводит категории, список порциями по 100 и карточку. `osm-export.js` сохраняет состав полей, метаданные GeoJSON, BOM, разделители CSV и защиту от формул v0.2. `osm-enrichment.js` вызывает существующий `POST /api/cadastre/enrich` по отдельной кнопке; ответ закреплён за исходным объектом, включая выбор кандидата и исходные характеристики.

Оранжевый буфер и его ореол используют один GeoJSON последнего принятого исследования. Легенда и кадастровая заливка читают общие `categories` из `cadastre-format.js`. `attribution.js` собирает кредиты Esri из действующего адаптера и одну строку OSM по реально используемым источникам данных. Боковая панель учитывает измеренную высоту кредитов.

## Ошибки и восстановление

| Сигнал нового API | Интерфейс и восстановление |
|---|---|
| 422 `invalid_input`, `missing_contour`, `request_budget_exceeded`, `radius_disabled` | Ошибка рядом с параметром или исходным объектом; дать поправить номер/точку/радиус либо выбрать участок с контуром. |
| 404 `source_not_found` | Показать отсутствие подтверждённого точного участка; дать проверить номер. Пустая территориальная выдача имеет 200 с фактическими счётчиками. |
| 409 `busy`, `source_changed` | Для занятости сохранить карту и предложить повтор позже; для ревизии обновить исходный и подтвердить повтор. |
| 403 `upstream_forbidden`; 429 `cooldown` с Retry-After | Указать слой/операцию, сохранить принятый результат. На 429 показывать интервал до ручного повтора. Технические URL и ключи исключены. |
| 502 `invalid_response/incomplete_response/response_budget_exceeded`, 503 `upstream_unavailable/tls_configuration`, 504 `deadline_exceeded` | Объяснить причину, что осталось на карте, дать повтор или меньший радиус после слишком большой/неполной выдачи. Старые HTTP/доменные ответы отображаются через клиентские адаптеры. |
| Отмена/устаревание | Статус конкретной операции завершается без изменения карты. Поздние ошибки также игнорируются. Другой слой не затрагивается. |

Ошибки `POST /api/cadastre/research` возвращают `{detail:{code,message},coverage,request_id}`, включая ошибки валидации. Остальные маршруты сохраняют ответы своих этапов. Для будущего общего сервера согласовать доступ пользователей, права на публикацию данных, egress, политику провайдеров и срок хранения кеша до развёртывания.

## Рабочие исследования (5.1)

Хранилище по умолчанию находится в `data/researches` от корня проекта. `RESEARCHES_DIR` в окружении backend задаёт другой постоянный каталог. Исследования независимы от кешей НСПД, Overpass и Nominatim. Запись создаётся только по команде «Новое». При создании можно сохранить текущий опорный ориентир и исходный участок, а выборки начинаются пустыми. В операционной модели один активный черновик на каталог. `active.json` содержит его UUID, чтобы после перезапуска предложить «Продолжить исследование». Закрытие снимает этот указатель и очищает карту, сохранённые данные остаются доступны из списка.

| Файл | Содержимое схемы 1 |
|---|---|
| `<uuid>/research.json` | UUID, название, признак ручного названия, адрес и номер, даты UTC, `schema_version`, счётчик `revision`, сводка и контрольные суммы наборов. `state` хранит точку, камеру, подложку, вкладку, режим карты, слои, выбранные радиусы, категории, фильтр безымянных и выбранные ID. |
| `<uuid>/cadastre.json` | `source` с геометрией и `result` с фактическим буфером, соседями, серверными измерениями, полнотой и датой. Геометрия исходного участка хранится один раз. |
| `<uuid>/osm.json` | `result` с GeoJSON, опорой, фактическим радиусом, датой, измерениями и атрибуцией, а также `requested_categories`. Текущие фильтры и выбор находятся в `research.json.state`, чтобы их изменение не переписывало GeoJSON. |

Пустой набор хранится как `null`. Название по умолчанию берётся из фактического адреса участка с номером в скобках. Точки снимаются у известных адресных сокращений. При отсутствии адреса используется номер, при отсутствии номера — координаты или «Новое исследование». Ручное название сохраняется при следующей смене исходного. В хранилище не попадают ключ подложки, URL кеш-провайдера, результаты временных ошибок или текущие карточки кадастрового обогащения OSM.

| Маршрут | Действие |
|---|---|
| `GET /api/researches` | Список из метаданных по убыванию даты изменения. |
| `GET /api/researches/active` | Сводка активного UUID для кнопки продолжения. |
| `POST /api/researches` | Создание и активация с `{state,cadastre?}`. В `cadastre` допускается только исходный участок. |
| `GET /api/researches/{id}`, `POST /api/researches/{id}/open` | Чтение `{research,cadastre,osm}`. Только POST устанавливает активный UUID после проверки файлов. |
| `PUT /api/researches/{id}` | `{revision,state,title?,cadastre?,osm?}`. Отсутствие ключа набора оставляет прежний файл. Явный `null` очищает набор. Успех возвращает актуальные метаданные и ревизию. |
| `POST /api/researches/{id}/close` | `{revision}`. Закрывает активный черновик после проверки версии. |

Фронтенд ждёт 480 мс после серии изменений и отправляет их последовательно с последней подтверждённой ревизией. Большие наборы отправляются при их фактической замене. Статус «Сохранено» выставляется после подтверждения сервера. Сбой оставляет черновик в памяти и кнопку повтора. Перед сменой исследования клиент сохраняет текущий черновик. Ошибка оставляет его открытым. Восстановление собирает геометрию и карточки из JSON, включая сохранённую OSM-выборку старше суток при совпадающих параметрах. НСПД, Overpass и Nominatim вызываются только явными действиями пользователя. Для подложки возможна обычная загрузка тайлов.

Запись синхронизируется блокировкой каталога. Ожидаемая ревизия и активный ID проверяются вместе. Устаревшая запись получает 409. Подготовленные файлы записываются во временные файлы в том же каталоге и заменяются атомарно. `research.json` меняется последним. Во время замены резервная копия изменяемого набора доступна по контрольной сумме предыдущего состояния. Временные резервные копии служат восстановлению при прерывании операции. На открытии сервер проверяет UUID, версию, контрольные суммы, форму GeoJSON, число объектов и координат. Лимиты файлов — 256 КиБ, 24 МиБ и 32 МиБ соответственно, до 15 000 объектов и 500 000 координат в наборе. Повреждённый или отсутствующий файл даёт 422 с названием файла, ошибка записи — 503, превышение размера — 413.

Пользовательские профили и независимые активные черновики в разных вкладках не предусмотрены. При конфликте сохранения локальный черновик остаётся в памяти. После аварийного закрытия браузера восстанавливается последнее состояние, подтверждённое сервером.

## Кадастровые отчёты (CR-006.6)

`GET /api/researches/{id}/reports` читает манифест и кадастровый набор активного исследования. Блокировка удерживается только при чтении согласованной ревизии. Backend проверяет пересечение сохранённого буфера, определяет румбы и сопоставляет ВРИ по локальному справочнику. Браузер показывает и экспортирует одну и ту же прочитанную выборку. [Состав таблиц, справочник и экспорт](09_LAND_REPORTS.md).
