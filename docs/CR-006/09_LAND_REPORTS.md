# CR-006.6 · Отчёты по земельным участкам

В Map First откройте «Исследования» → «Отчёты». Диалог показывает название исследования, исходный кадастровый номер, фактический радиус, дату получения и статус полноты. Вкладки прокручиваются внутри диалога. «Скачать MD» выгружает открытую таблицу. Если выборки ещё нет, диалог предлагает выполнить и сохранить кадастровое исследование.

## Источник и выборка

При открытии диалога браузер выполняет `GET /api/researches/{id}/reports` для активного в интерфейсе исследования. Backend сверяет ID с указателем активного исследования и читает согласованную ревизию `research.json` и `cadastre.json` под существующей блокировкой. Проверки версии схемы, контрольных сумм и исходного участка общие с хранилищем CR-006.5.1. После чтения блокировка освобождается, и backend формирует строки. OSM-файл не читается. Геосервисы и записи в хранилище из маршрута отчётов не вызываются. При смене активного исследования в другом окне сервер возвращает 409.

Обе вкладки и выгрузки используют одну прочитанную ревизию. Если на момент открытия есть несохранённые изменения, диалог предлагает дождаться подтверждения и открыть отчёты снова. Пока диалог открыт, набор строк остаётся согласованным с показанными метаданными.

| Вкладка | Колонки |
|---|---|
| Все участки | №, кадастровый номер, категория земель, ВРИ, направление, расстояние в метрах |
| Нормируемые земли | №, кадастровый номер, исходный ВРИ, группа использования или причина проверки, статус ВРИ, направление, расстояние в метрах |

В первую таблицу входят все сохранённые соседние участки, чьи геометрии пересекают сохранённый буфер WGS 84, включая касание контура буфера. Исходный номер исключается, остальные номера уникальны. Отсутствие категории или ВРИ не влияет на включение. Сортировка идёт по точному сохранённому расстоянию и числовым частям номера, строки без измерения идут последними. Некорректный исходный контур или буфер блокирует отчёт. При пропуске некорректных соседних контуров отчёт показывает число пропусков и статус «Неполная выборка».

Расстояние берётся из сохранённого измерения между границами. Соприкосновение и пересечение отображаются как `0,00`. Направление рассчитывается отдельно по прямому геодезическому азимуту WGS 84 от внутренней точки исходного полигона до внутренней точки соседнего. Для мультиполигона берётся внутренняя точка всей геометрии по алгоритму Shapely. Азимут разбивается на восемь секторов по 45° с центрами по румбам С, СВ, В, ЮВ, Ю, ЮЗ, З, СЗ. При совпадении точек с точностью 1 мм или неопределимом азимуте выводится «Не определено». Статус «Полнота подтверждена» возможен только при явном подтверждении в сохранённых метаданных.

## Правила ВРИ

В сохранённой выборке `permitted_use` содержит текст ВРИ из сведений НСПД. В проекте есть примеры свободного текста, в том числе описания эксплуатации предприятия. Для первоначального отбора используется локальный [справочник ВРИ 1.0.0](../../app/static/map-first/land-use-rules.v1.json), содержащий точные коды и наименования. Справочник разделяет жилую застройку, образование, здравоохранение, рекреацию и отдых, спортивные объекты. Группы используются для предварительного отбора кандидатов на проверку применимых норм. Основание для кодов и названий — [приказ Росреестра № П/0412](https://publication.pravo.gov.ru/document/0001202012160040) и [изменения № П/0278/26](https://publication.pravo.gov.ru/document/0001202609040013).

| Запись ВРИ | Результат |
|---|---|
| Точный код, точное наименование или согласованная пара из записи справочника | Включение во вторую таблицу с группой правила |
| Смешанный или свободный текст, отсутствующий ВРИ, неизвестное правило, несовпадение кода и названия | Включение со статусом «Требует проверки» и причиной |
| Точное совпадение с явно заданным правилом вне групп отбора | Участок остаётся в первой таблице. Во второй он учитывается в счётчике «Вне групп отбора» |

При сопоставлении нормализуются регистр, `ё`, пробелы и варианты дефиса. Коды проверяются целиком, наследование по префиксу и поиск по подстроке отсутствуют. Исходное поле остаётся в таблице. Список исключений ограничен двумя точными позициями, производственной деятельностью `6.0` и улично-дорожной сетью `12.0.1`. Код ВРИ сам по себе не устанавливает фактическое использование участка или применимый санитарный норматив.

Подтверждённые совпадения и строки «Требует проверки» отображаются отдельными разделами внутри одного отчёта. Каждый раздел сохраняет порядок по расстоянию и номеру. В неоднозначной строке выводятся исходный ВРИ, статус и отдельная причина. Те же разделы и статусы входят в одну выгрузку `lands_normalized_<радиус>m.md`.

Перед расширением справочника требуется согласовать предмет отбора и конкретные нормы, охват специальных и смешанных ВРИ, в том числе ЛПХ, санаториев и спортивных объектов, а также сверку с фактическим использованием. Изменения списка требуют новой версии справочника и ссылки на проверенный источник.

## Markdown

Кнопка скачивает `lands_all_<радиус>m.md` или `lands_normalized_<радиус>m.md` в UTF-8. В файле указаны отдельно дата получения данных и дата формирования в UTC, статус полноты и происхождение данных. Расстояния округляются до двух знаков с запятой. Пропуски отображаются как «Нет сведений», неопределённый румб — «Не определено». В полях экранируются разметка Markdown, HTML и разделитель таблицы `|`, переносы заменяются пробелами. Повторное скачивание формирует новую дату выгрузки.

Примеры на синтетической выборке — [все участки](examples/lands_all_500m.md) и [нормируемые земли](examples/lands_normalized_500m.md).

## Ручная приёмка

1. Откройте сохранённое исследование с кадастровой выборкой. В меню «Исследования» выберите «Отчёты».
2. Сверьте исходный номер, фактический радиус, даты, полноту и количество участков. Проверьте ближайшие строки, отсутствие исходного номера и наличие строк с неизвестными ВРИ и категорией.
3. Переключите вкладку «Нормируемые земли». Сверьте группы и причины проверки неоднозначных строк. Скачайте обе таблицы, откройте файлы в редакторе Markdown и сравните их с вкладками.
4. Откройте диалог у исследования без выборки. Убедитесь, что предлагается выполнить кадастровое исследование. В Network при открытии отчёта ожидается локальный GET, при выгрузке создаётся файл в браузере.
