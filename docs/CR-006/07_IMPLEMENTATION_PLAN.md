После каждого этапа предоставить короткий отчёт о реализованной функциональности, запуске, результатах smoke и действиях для ручной приёмки. Явно перечислить непроверенные сценарии. Большой новый автотестовый набор, массовые регрессии, нагрузочные и повторные браузерные прогоны не входят в условия завершения. Существующие тесты сохраняются. Массовые реальные запросы к НСПД и Overpass исключены. [Облегчённая приёмка](06_ACCEPTANCE_TESTS.md)

Этапы 1–4 могут поставляться по тестовым флагам в одном backend. Порядок UX-приёмки — кадастр, затем OSM. Переезд в Docker самостоятелен и не блокирует локальную проверку. Для многопользовательской среды проверить внешний HTTPS origin, политику токена/атрибуции, общую очередь и кеш на репликах до масштабирования.

В поставке 3.2 рабочий экземпляр запускается с доступными 500 м и выключенными 1000/2000 м. На стенде с фикстурами флаги `NSPD_RESEARCH_ENABLE_1000` и `NSPD_RESEARCH_ENABLE_2000` могут быть включены независимо. Для допуска реальной выдачи каждый радиус согласовывается отдельно. Откат допуска — снять соответствующий флаг и перезапустить backend. Проверка на предельных объёмах, живые гарантии НСПД и многопроцессная координация остаются за пределами smoke. [Параметры](04_ARCHITECTURE.md#допуск-радиусов) · [Ручная проверка](06_ACCEPTANCE_TESTS.md#ручная-проверка-этапа-32)

## Риски

| ID | Риск и последствия | Снижение / проверка |
|---|---|---|
| R-01 | НСПД выдаёт скрыто усечённый набор или меняет схему. Точный итог по всем участкам не доказуем. | Явные признаки дают отказ, отсутствие подтверждения маркируется unknown. Проверить один неполный ответ на фикстуре и согласовать допуск. |
| R-02 | Плотные/сложные территории. B2000 уже давал 3016 объектов и около 9,17 MB декодированных данных на одном участке. Растут CPU и объём. | Серверные лимиты, одно обращение без дробления, Canvas и индекс попаданий. Оставить доступным меньший радиус. Количественный профиль производительности фиксируется отдельно при необходимости. |
| R-03 | Nominatim находит точку адреса, которая не совпадает с участком. Наблюдавшийся порядок осей WMS расходится с текущим кодом. | Отдельное подтверждение, локальная геометрия, переход к номеру. Проверка подбора на фикстуре. |
| R-04 | Процессный lock не ограничивает все вызовы между воркерами, браузерная отмена не прерывает провайдера автоматически. Возможны 429 и повторные обращения. | Общий лимитер и single-flight, ограниченная очередь и один worker до межпроцессной координации. Smoke обработки 429 на локальном ответе. |
| R-05 | Несовпадающие версии динамически читаемой статики и загруженных маршрутов, как на 8001. | Поставлять backend и статику вместе. Проверить маршрут, health и загрузку страницы с одного origin. |
| R-06 | Esri отклоняет внешний referrer, исчерпывается квота или снимки здесь хуже по детализации. | Проверка с конечного origin, ограничения токена, соблюдение атрибуции и явный возврат в OSM. |
| R-07 | Ошибочный выбор при перекрытии, неверное расстояние при визуальном упрощении. | Единые правила попаданий, список вариантов, полная геометрия для измерений. Ручная проверка после подключения слоёв. |
| R-08 | Утрата старых функций OSM (выгрузка, фильтры, обогащение) и перегруженная узкая раскладка. | Ручной проход по этим функциям и узкой раскладке. Старые страницы доступны до отдельного решения. |
| R-09 | Общий IP создаёт совокупную нагрузку на публичные Nominatim/Overpass/тайлы. | Оператор определяет провайдеров, политики и квоты. Ограничивать совокупный трафик и соединения, сохранять атрибуцию. |
