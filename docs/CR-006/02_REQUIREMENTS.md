# CR-006 · Техническое задание Map First

Статус — проект к согласованию. Цель — единое браузерное рабочее место исследования территории, где основное действие работает с земельными участками ЕГРН, а данные OSM подключаются по запросу. Базовый срез миграции описан в [обследовании](01_CURRENT_STATE.md).

## Функциональные требования

| ID | Требование |
|---|---|
| FR-001 | Один основной экран с одним экземпляром Leaflet. Карта заполняет рабочую область окна. Поверх неё компактные поиск, «Исследовать», радиус, кнопки панели и «Вся карта». Старт — рабочий режим с закрытой панелью. |
| FR-002 | Универсальный поиск по отправке формы. Приоритет распознавания — полный кадастровый номер, пара координат, адрес. Похожие на номер или пару координат некорректные значения получают подсказку формата без запроса. Запуск по «Найти»/Enter, ручной выбор кандидатов сохранён. |
| FR-003 | Точный кадастровый номер загружает земельный участок и выделяет валидный контур. При отсутствующем контуре объяснить ограничение исследования. Найденный номер сверяется с запросом; противоречивые контуры требуют отказа с причиной. |
| FR-004 | Адресный поиск через Nominatim показывает кандидатов на выбор. Адрес, ввод координат и явное задание точки на карте дают ориентир. «Найти участок у точки» запускает кадастровый подбор отдельным действием. Кандидаты показывают отношение к точке и статус геометрии. Исходным становится один явно подтверждённый участок с валидным площадным контуром. Ориентир перетаскивается в режиме редактирования, как в v0.2. |
| FR-005 | Радиусы 500, 1000 и 2000 м. Стартовый 500 м. Смена радиуса обновляет параметры и доступность действий с нулём запросов. |
| FR-006 | «Исследовать» запускает только земельное исследование НСПД по подтверждённому контуру и выбранному радиусу. Метрический буфер строится от исходного участка, соседи — уникальные валидные земельные контуры, пересекающие буфер, кроме исходного. Без контура кнопка недоступна с пояснением. Большие радиусы проходят ограничения NFR-003 и этапы допуска. |
| FR-007 | При смене радиуса и повторном исследовании того же участка старая выборка остаётся видимой с отметкой фактического радиуса и свежести. Замена атомарна после принятия подходящего ответа. Отказ, отмена и явная неполнота транспорта сохраняют предыдущий результат. Явный выбор другого исходного участка убирает чужие результаты с карты и сохраняет их по ключу в пределах TTL. |
| FR-008 | Подложки «Карта» (OSM) и «Спутник» (Esri). Одновременно одна. Смена затрагивает тайлы, атрибуцию и статус подложки. При отсутствующей конфигурации спутник недоступен с объяснением, при отказе можно одним действием вернуться на карту. |
| FR-009 | Кнопка «Слои» открывает переключатели кадастровых границ, номеров, заливки по категориям земель и объектов OSM. Стартовые флаги: границы и номера включены, заливка и OSM выключены. Флаги и данные переживают закрытие панели и скрытие слоя. [Матрица слоёв](03_UI_UX_DESIGN.md#матрица-слоёв) |
| FR-010 | Включение «Объекты карты» с известным ориентиром использует свежий результат под параметры, совместный незавершённый запрос либо один вызов OSM. Пока точки нет, показать нужное действие и сохранить намерение. Отключение скрывает геометрию, сохраняя данные и выбор. Изменение радиуса/ориентира сразу скрывает несовпадающий набор; явное «Загрузить объекты» или повторное включение запрашивает новый ключ при cache miss. Загрузка и ошибки OSM независимы. |
| FR-011 | Девять категорий v0.2 и правила классификации сохранены. Вкладка «Объекты» показывает полученные/видимые количества и разбивку, фильтры категорий и безымянных, список с выводом порциями, сброс фильтров, выбор и переход. Карточка показывает имя, тип, основание, теги, ссылку OSM, дистанцию и направление. Сохранить линию OSM, экспорт отфильтрованного набора GeoJSON/CSV с фактическими параметрами и явное кадастровое обогащение выбранного объекта с выбором кандидата. Его поля и правовой смысл отделены от OSM-атрибутов. |
| FR-012 | Панель имеет вкладки «Кадастр», «Объекты», «Координаты». «Кадастр» показывает исходный объект, выбранный и фактический радиусы, число показанных участков и соседей, сводку категорий с «Нет данных», выбранный участок, характеристики, топологический статус, дистанцию и предупреждения. Соседи — выборка без исходного, соприкасающиеся — отдельный счётчик. |
| FR-013 | «Координаты» показывает курсор при наличии мыши, выбранную точку, поля WGS84, переход и копирование. Поддержать знаки, дробную точку/запятую в отдельных полях и копируемую пару lat, lon. Клик по фону задаёт справочную точку. «Использовать как ориентир» переводит её в исходные параметры. Переход к координатам меняет камеру и справочную точку. |
| FR-014 | Выбор участка или объекта OSM открывает соответствующую вкладку и выделяет объект. В перекрытии приоритет последней активной предметной вкладки, по умолчанию кадастр. Кнопка «Объекты в точке» позволяет выбрать любое попадание без отключения слоёв, в том числе касанием. Клавиатурный выбор доступен из списков. Скрытый слой исключён из попаданий. |
| FR-015 | Стили кадастра сохраняются по [дизайну](03_UI_UX_DESIGN.md#картография). Для disjoint — длина и линия между точками границ. Для touches/intersects — 0 м и разный текстовый статус. Для undefined — «Расстояние не определено». При выборе исходного — «Исходный участок». |
| FR-016 | Рабочий режим, режим с панелью и режим «Вся карта». В «Вся карта» скрываются поиск и панели, остаются выход, навигация, атрибуция, инструменты карты и компактный индикатор фоновой операции. Выход кнопкой и Esc восстанавливает режим и фокус. Системное полноэкранное действие отделено от режима приложения. |
| FR-017 | Источник, выбор, данные, радиус, линии, центр, zoom и видимость переживают смену подложки, панели, вкладки, режима и размеров. При скрытии слоя его выделение и линия скрываются визуально с сохранением состояния. Новый набор восстанавливает выбор по ID при наличии; иначе — исходный для кадастра и пустой выбор для OSM. «Показать область исследования» подгоняет вид к фактическому буферу. |
| FR-018 | Метрическая шкала, zoom, сворачиваемая легенда, число видимых информационных слоёв, индикаторы занятости/неполноты и атрибуция. Панель закрывается одним действием, на узком экране становится нижней. Карта интерактивна вне плавающих элементов. |
| FR-019 | Отдельно различать ожидание, готовность, пустой корректный результат, неизвестную полноту, подтверждённые пропуски, ограничение, отмену и ошибку. Показывать фактические количества, свежесть и пропуски. Отсутствующее поле — «Нет данных». Действие восстановления зависит от причины. |
| FR-020 | Сохранить обе прежние страницы и контракты в период миграции. Новый интерфейс сначала на отдельном маршруте, затем становится основной страницей после проверки. Вывод старых страниц — отдельное решение. |

## Нефункциональные требования

| ID | Требование и способ измерения |
|---|---|
| NFR-001 | Один FastAPI, один Leaflet на рабочей странице. Относительные URL API, один origin, готовность к Docker/HTTPS. Сохранены существующие способы запуска в период миграции. |
| NFR-002 | Внешние запросы выполняются по явным действиям инструмента после проверки актуального кеша и выполняющейся операции. Смена подложки, размеров/режима, вкладки, подписей/заливки, pan/zoom и выбор загруженного объекта дают ноль вызовов НСПД/Overpass. Тайлы самостоятельны. |
| NFR-003 | Максимум один одновременный upstream-запрос к НСПД на экземпляр общего лимитера. Обязательны межзапросный интервал, учёт Retry-After, ограничения входной геометрии, декодированного тела, количества и дедлайна. Политика охватывает территориальные запросы, подбор, lookup и обогащение. [Профиль и допуск](04_ARCHITECTURE.md#безопасная-загрузка-нспд) |
| NFR-004 | Отменённый/устаревший ответ исключается из коммита UI. Один выполняющийся запрос на ключ, отдельные ключи для источников и радиусов. Ожидание, отмена и лимиты сохраняют последнее принятое состояние. |
| NFR-005 | Проверить 1920×1080, 1366×768, уменьшенное окно 640×480, планшет 768×1024 и узкий 390×844. Минимальная ширина 320 CSS px. Горизонтальной прокрутки документа нет. Основные действия доступны с экранной клавиатурой, атрибуция помещается с переносом. |
| NFR-006 | Клавиатура, видимый фокус, доступные имена, статусы и ошибки, Esc и возврат фокуса для раскрывающихся элементов. Целевой размер кнопок ≥44×44 CSS px, служебный текст ≥12 px, основные подписи ≥14 px. Контраст текста ≥4,5:1, значимых элементов управления ≥3:1. |
| NFR-007 | Цель локальной приёмки на согласованном стенде: статус ≤200 мс, p95 от готового клиентского GeoJSON до первого нанесения ≤1,5 с для 600 и ≤3 с для 4000 участков без времени сети/тайлов. Точные измерения используют исходную геометрию; визуальная оптимизация сохраняет выборку. |
| NFR-008 | Проверяемые TLS и имя сервера НСПД. Браузерный токен Esri с минимальными правами и разрешённым внешним referrer. Исключить ключи и полные авторизованные URL из файлов сборки, логов и тел ошибок. Атрибуция используемых поставщиков видима в допустимом месте. |
| NFR-009 | TTL, ограниченные объём и размер кеша, атомарная запись, отказ на битом формате, статус покрытия и границы применимости. Журналы содержат ID, тип операции, радиус, количество, размеры, длительности, кеш/код ошибки без токенов, полных запросов и точных адресов/координат. |
| NFR-010 | Регрессии на контролируемых ответах, API-контрактах и двух старых страницах. Автоматическая приёмка без сети провайдеров. Живая проверка больших радиусов — отдельный согласованный этап. |
