# CR-006 · Вопросы к согласованию

| ID | Что подтвердить | Предложение для ТЗ | Когда |
|---|---|---|---|
| Q-01 | Разрешённый режим обращения к НСПД, договорённость о полноте, лимитах и пагинации. Кто утверждает допуск 1000 и 2000 м? | Считать полноту неизвестной без доказательства. Включать радиусы раздельно после офлайн-приёмки и согласованной проверки у поставщика. Нужны разрешённые территории и бюджет единичных проверок. | До разработки/допуска больших радиусов |
| Q-02 | Профиль бюджетов и что делать при отказе на плотном участке: 60 км²/6000 координат, 16 MiB/5000 записей, 35 с, интервал 3 с, кеш 512 MiB. | Уточнить на локальных фикстурах, затем конфигурировать; сохранять предыдущую выборку. Черновые значения — пределы приложения, квоты провайдера проверяются отдельно. | До реализации безопасного API |
| Q-03 | Правило подбора исходного по адресу/точке и допустимость близких участков. Нужны ли несколько исходных контуров? | Один явно подтверждённый контур. Окно 15 м, визуальное отношение и ручные координаты/номер; близкий участок выбирается осознанно. Несколько исходных контуров требуют отдельной спецификации области и расстояния. | До реализации поиска |
| Q-04 | Центр OSM при поиске по номеру и момент обновления после смены параметров. | Взять явно выбранный ориентир; если только номер — внутреннюю точку участка. Загрузку для нового ключа делать по команде, с отметкой «от точки». | До согласования сценариев OSM |
| Q-05 | Как показывать неполные выдачи и счётчики. | Явное усечение транспорта сохраняет прежний результат. Обработанный набор при локальных пропусках показывается с предупреждением без дискового кеша. «Соседи» — вся выборка без исходного, касания видны отдельно. | До утверждения UI и API |
| Q-06 | Общий сервер, доступ пользователей, публичный origin/префикс, разрешённые провайдеры и бюджет Esri/OSM. | Один worker до общей координации, HTTPS, ограниченный кеш, браузерный ключ Esri с referrer конечного сайта. Политику публичных тайлов, геокодера и Overpass подтвердить отдельно. | До развёртывания |
| Q-07 | Нужен ли браузерный полноэкранный режим в первом релизе, срок поддержки старых страниц и владельцы решения о переключении. | «Вся карта» средствами интерфейса доступна всегда. Fullscreen API — отдельная команда при поддержке. Срок отключения старых страниц согласовать после регрессии. | До приёмки режимов и переключения |
| Q-08 | Эталонный стенд, перечень браузеров/устройств и фиксируемые метрики NFR-007. | Chrome/Edge на рабочей станции и ноутбуке, планшет и телефон с экранной клавиатурой, согласованные фикстуры на 600/4000 участков. | До замеров |

Зафиксированные допущения проекта ТЗ: один исходный земельный участок; интерфейс с административно отключаемыми радиусами; сохранение состояния внутри сессии страницы; OSM-классификатор и точечная метрика v0.2; одно приложение с доступными прежними страницами в период миграции. Реализация, развёртывание, переключение маршрутов и новые живые серии НСПД начинаются по отдельному подтверждению.
