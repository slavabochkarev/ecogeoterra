# Технический долг и ограничения

**Назначение** — зафиксировать подтверждённые расхождения, зоны риска и непроверенные сценарии для отдельной приоритизации. P1 — ограничение эксплуатации или риск потери корректности, P2 — значимый долг разработки/проверки, P3 — поддерживаемость и документация.

| ID | Проблема | Где обнаружена | Последствие | Приоритет |
|---|---|---|---|---|
| TD-01 | Нет авторизации, раздельного владения и изоляции активного исследования | `main.py`, `research_api.py`, `ResearchStore._active` | Любой клиент с доступом к порту может работать с общим каталогом и менять активный UUID. Публичное размещение требует отдельного решения. | P1 |
| TD-02 | Сетевые лимитеры и одноразовая обработка запросов действуют только в процессе | `CachedService.lock/next_allowed`, `CadastreService.lock/next_allowed`, `CadastreResearch.flights` | Несколько workers/экземпляров могут параллельно обращаться к НСПД и нарушать суммарный лимит Nominatim. Кеш bounded может очищаться конкурентными процессами. Многопроцессный режим не подтверждён. | P1 |
| TD-03 | НСПД не подтверждает полноту обычной выборки | `CadastreResearch._research`, `nspd.collection`, приёмка CR-006.6.1 | Явное усечение отклоняется; незаявленные пропуски возможны. На 1000 м получен рабочий результат, точные байты и статус не зафиксированы из-за ошибки замера. Живой допуск 2000 м и крайние случаи плотных территорий не подтверждены. | P1 |
| TD-04 | Параметры Overpass QL ограничивают исполнение у поставщика, локальный объём ответа не лимитируется отдельно | `services.build_query/CachedService.request`, `main.analyze` | Большие ответы целиком загружаются и разбираются, затем геометрия обрабатывается синхронно. Риск памяти, долгого ответа и повторов из-за пользователей нескольких процессов. | P1 |
| TD-05 | Часть кешей растёт до ручной очистки, для хранилища нет общей квоты | `CachedService`, `CadastreService`, `ResearchStore`. Вытеснение есть у `CadastreResearch._write_cache` внутри `research-v2` | Истёкшие файлы могут занимать диск. Исчерпание места мешает сохранению. | P2 |
| TD-06 | Несколько frontend для близких задач | `app.js`, `cadastre-experiment.js`, `map-first` | Дублирование базовых обработчиков подложек, подписей, координат и экспорта. Контракты ошибок и UX legacy отличаются, требуется отдельная проверка при изменениях. | P2 |
| TD-07 | Условная совместимость старых backend-процессов с обновлённой статикой | `StaticFiles`, сравнение OpenAPI 8001/8002/8003; общий health 0.2.0 | Совпадение HTML/версии не означает поддержку API. В частности 8001 не знает endpoint конфигурации Esri, у 8001/8002 нет маршрута Map First. | P2 |
| TD-08 | Часть тестов современных сценариев существует как разовые smoke, без постоянных сценариев в `tests` | [Приёмка CR-006](../CR-006/06_ACCEPTANCE_TESTS.md) и [инвентаризация](01_PROJECT_STRUCTURE.md#тесты-и-эксплуатационный-код) | Автосохранение, восстановление, отчёты и текущий адаптивный UI сложнее перепроверить после изменений. Реальные провайдеры и сценарии на нескольких workers отдельно не пройдены. | P2 |
| TD-09 | Отчёты отбирают сохранённые участки повторным пересечением в WGS 84, исходная выборка отсечена в AEQD | `land_reports.build_reports` и `cadastre_experiment.land_collection` | На границе, особенно при длинных сегментах, топология после проекции может отличаться. Влияние на предельных контурах не подтверждено. | P2 |
| TD-10 | Локальный справочник ВРИ ограничен точными записями и не проверяет реальное использование | `land-use-rules.v1.json`, `_classification` | Старые, свободные и смешанные формулировки требуют ручной проверки. Применимые нормативы должны определяться отдельно. | P2 |
| TD-11 | WMS и часть методов сохраняются ради legacy или диагностики | `NspdGateway.search` — вызывается `CadastreService.enrich` со старой страницы. `by_number(land_only=False)` — диагностический путь, публичного маршрута для общего scope нет. `GET /api/researches/{research_id}` не нужен кнопке Open, которая вызывает POST. | У этих ветвей разные клиенты. Отсутствие вызова в Map First не доказывает, что код можно удалить. | P3 |
| TD-12 | Неполный машинный контракт | `research_api.payload` вручную читает body, а заметная часть FastAPI-обработчиков строит словари без response_model | OpenAPI отражает маршруты, но для генерации контрактного клиента недостаточно полной схемы. | P2 |
| TD-13 | Геометрия и таблицы рендерятся в браузере, а обработчики backend выполняют CPU/I/O синхронно | `cadastre-map.prepare`, `osm-map.js`, `land-reports.js` и `main.analyze` | Крупная выборка может заметно задержать браузер и worker thread. Ограничения проверены локально, предельная производительность не подтверждена. | P2 |
| TD-14 | Зависимость от внешних сервисов и внутреннего метода pynspd | `SecureNspd._build_client`, Nominatim/Overpass/OSM/Esri в [Integration Design](03_INTEGRATION_DESIGN.md) | Изменение TLS, схемы внешнего ответа, условий использования или ключа может нарушить работу. Локальный кеш не обеспечивает живой SLA. | P2 |
| TD-15 | Нет установленной Git-ревизии рабочей копии и достоверной связи с готовыми ZIP | `git rev-parse --verify HEAD` не находит репозиторий; отдельные версии в корне, общий health 0.2.0 | Сложно сопоставить запущенные экземпляры, исходники и артефакты по одному номеру версии. | P3 |

## Расхождения прежней документации и текущего кода

| Источник | Что уточнено |
|---|---|
| [Корневой README](../../README.md) описывает v0.2 и файловый кеш внешних API | Корневой маршрут действительно остаётся v0.2. У `/map` теперь есть отдельное постоянное хранилище и два MD-отчёта. CSV/GeoJSON продолжают формироваться в браузере. |
| [Первичное обследование CR-006](../CR-006/01_CURRENT_STATE.md) фиксирует 8001/8002 и прежние маршруты | Это исторический срез. На 8003 есть `/map`, bounded кадастр, исследования и отчёты. Номер версии процесса остался общим. |
| [FR-011](../CR-006/02_REQUIREMENTS.md) и [архитектура CR-006](../CR-006/04_ARCHITECTURE.md) описывают явное кадастровое обогащение OSM в Map First | CR-006.6.1 убрал действие из Map First. `/api/cadastre/enrich` и legacy `app.js` сохраняют его. |
| [Сценарии CR-006.5.1](../CR-006/05_USER_SCENARIOS.md) описывают перенос исходного в новый черновик | API по-прежнему допускает создать запись с одним исходным участком. Текущее меню `study-new` отправляет только пустое рабочее состояние с текущими камерой и подложкой. |
| [План CR-006](../CR-006/07_IMPLEMENTATION_PLAN.md) предусматривает перевод Map First на корневой маршрут и вывод старых страниц | В коде план не выполнен: `/`, `/cadastre-experiment`, `/map` зарегистрированы отдельно. |
| [Радиусы CR-006 и приёмка](../CR-006/06_ACCEPTANCE_TESTS.md) описывают несколько профилей допуска | По умолчанию только 500 м. На 8003 наблюдались 500 и 1000 м. 2000 м проверен с флагом на фикстурах, живой допуск не подтверждён. |
