# Доверенный CA только для клиента НСПД

`russian_trusted_root_ca.pem` — публичный сертификат **Russian Trusted Root CA**.

- Официальный источник: https://gu-st.ru/content/Other/doc/russian_trusted_root_ca.cer (CDN портала Госуслуг; `gu-st.ru` указан также в ресурсах официальной страницы https://www.gosuslugi.ru/crt).
- Получен 13 ноября 2026 года через HTTPS с обычной проверкой сертификата и hostname (`httpx`, `verify=True`, без прокси). Ответ HTTP 200. Приватных ключей нет.
- DER SHA-256: `D26D2D0231B7C39F92CC738512BA54103519E4405D68B5BD703E9788CA8ECF31`.
- Subject и Issuer: `C=RU, O=The Ministry of Digital Development and Communications, CN=Russian Trusted Root CA`.
- Действует: 1 марта 2022 21:04:15 UTC — 27 февраля 2032 21:04:15 UTC.
- BasicConstraints: `CA:TRUE, pathlen:4`. SAN у корневого сертификата отсутствует; имя сервера проверяется по SAN конечного сертификата.

Сертификат независимо получен из официального источника. После этого его DER-отпечаток сопоставлен с корнем цепочки сервера. Проверены подписи цепочки, назначение SSL server, сроки и hostname `nspd.gov.ru` через OpenSSL и живое защищённое TLS 1.3 соединение. Корень из непроверенного handshake не используется как источник доверия.

Адаптер добавляет CA только в собственный `SSLContext`. Системные хранилища Windows, certifi, настройки других HTTP-клиентов и переменные окружения не меняются. Автоматического скачивания или обновления при запуске нет. Отпечаток встроенного файла проверяется перед загрузкой; несовпадение завершает операцию ошибкой. `CERT_REQUIRED` и `check_hostname=True` остаются включены. `NSPD_CA_FILE`, если явно задан, заменяет дополнительный встроенный CA, сохраняя системное доверие.

Не добавляйте сюда другие сертификаты без проверки происхождения. При официальной ротации проверяйте новый источник/отпечаток и тесты; не доверяйте новому корню только потому, что его прислал сервер.
