# ЭкоГеоТерра v0.2

[Техническая документация и интеграционный дизайн As-Is](docs/architecture/README.md) описывают текущий Map First, API, хранение и запуск.

Локальный прототип для проверки качества открытых геоданных вокруг промышленного объекта. Python 3.12, FastAPI, Shapely, PyProj и обычные HTML/CSS/JavaScript с Leaflet. Без LLM, базы данных, Docker и фронтенд-фреймворков.

Основной интерфейс [Map First](http://127.0.0.1:8000/map) поддерживает поиск по адресу, координатам и кадастровому номеру, исследования по НСПД и OpenStreetMap, сохранение исследований на диске и отчёты по земельным участкам. Доступны также прежний OSM-интерфейс `/` и кадастровый эксперимент `/cadastre-experiment`.

Результаты зависят от доступности, лимитов и полноты данных НСПД, Nominatim, Overpass и серверов картографических подложек. Используйте прототип для предварительного обследования территории. Подробнее в [описании интеграций](docs/architecture/03_INTEGRATION_DESIGN.md).

## Новое в исходниках v0.2: кадастровые сведения НСПД

Выберите один объект в правом списке «Объекты рядом» и нажмите **«Получить кадастровые сведения»** в его панели. Запрос выполняется по кнопке, не блокирует карту; при нескольких кандидатах требуется выбор пользователя. Показаны источник, дата получения и признак локального кеша (TTL по умолчанию 24 часа). Классификация и экспорт OSM не используют кадастровые характеристики.

Адаптер использует закреплённый `pynspd==1.1.15` с обязательной проверкой TLS и hostname. **TLS исправлен 13 ноября 2026 года:** недостающий `Russian Trusted Root CA` получен с официального CDN Госуслуг и добавлен только в контекст клиента НСПД. Поиск номера `63:09:0102159:753` и реальный поиск по контуру OSM `way/135674075` вернули HTTP 200; найден один кандидат — земельный участок с этим номером. В интерфейсе проверены реальные характеристики. Windows и certifi не изменялись; `NSPD_CA_FILE` для обычного запуска не нужен. Причина, сертификаты и протокол: [docs/NSPD_TLS_FIX.md](docs/NSPD_TLS_FIX.md).

Описание исходной интеграции, настроек и проверок доступно в [docs/NSPD_V02.md](docs/NSPD_V02.md). Для диагностики с живым запросом передайте в `scripts/check_nspd.py` локальный GeoJSON объекта OSM через `--osm-feature` и путь для результатов вне репозитория через `--output`.

**Windows-выпуск v0.2 пересобран 14 ноября 2026 года** с адаптером НСПД и проверенным CA. Архив `EcoburoGeo-v0.2-win64.zip` можно собрать по [инструкции для Windows](BUILD_WINDOWS.md). Готовая сборка запускается с комплектными Python и сертификатом.

## Переносимая Windows-версия (без Python)

Распакуйте `EcoburoGeo-v0.2-win64.zip` целиком и запустите `EcoburoGeo/EcoburoGeo.exe`. Не переносите один EXE без папки `_internal`. Появится окно «ЭкоГеоТерра v0.2», затем автоматически откроется браузер. Если порт 8000 занят, приложение выберет другой свободный порт. Сервер слушает только `127.0.0.1`.

Для завершения закройте окно приложения или нажмите «Завершить». Закрытие вкладки браузера само по себе сервер не останавливает. Интернет нужен для OSM, Nominatim и Overpass; EXE не делает эти сервисы доступными офлайн.

Кеш EXE: `%LOCALAPPDATA%\EcoGeoTerra\cache`, журналы: `%LOCALAPPDATA%\EcoGeoTerra\logs`. Эти каталоги создаются при использовании и не входят в ZIP. Переменная `CACHE_DIR` по-прежнему может переопределить папку кеша. У запуска из Python остаётся `.cache` в папке проекта.

Инструкции сборки и переноса — в `BUILD_WINDOWS.md`. Сборка Windows x64 через PyInstaller `onedir`; установка Python нужна только разработчику.

## Запуск исходников на Windows

Установите **Python 3.12 x64** с python.org. В PowerShell:

```powershell
git clone https://github.com/slavabochkarev/ecogeoterra.git
cd ecogeoterra
.\start.ps1
```

Скрипт создаёт `.venv`, устанавливает зависимости, открывает браузер и запускает один процесс Uvicorn на **http://127.0.0.1:8000**. При первом запуске нужен интернет для установки зависимостей. Если браузер открылся раньше сервера, обновите страницу через несколько секунд. Остановка — `Ctrl+C` в окне PowerShell.

Откройте [Map First](http://127.0.0.1:8000/map). Для спутниковой подложки Esri скопируйте `.env.example` в `.env` и укажите собственное значение `ESRI_API_KEY`.

Если политика PowerShell запрещает запуск этого локального скрипта:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\start.ps1
```

Для другого порта или запуска без открытия браузера:

```powershell
.\start.ps1 -Port 8001 -NoBrowser
```

Запуск вручную, в том числе на Linux/macOS с Python 3.12:

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8000 --workers 1
```

На Linux/macOS используйте `python3.12` вместо `py -3.12`, затем `.venv/bin/python` вместо `.venv\Scripts\python.exe`. Не запускайте несколько workers или копий приложения: встроенные ограничения частоты рассчитаны на один локальный процесс.

## Как пользоваться прежним OSM-интерфейсом

1. Введите адрес и нажмите **«Найти адрес»**. При вводе символов запросы не отправляются.
2. Выберите подходящий результат Nominatim. Даже единственный результат требует выбора: это может оказаться улица, территория или другое здание.
3. Проверьте точку. Перетащите маркер или включите **«Указать точку»** и нажмите на карту. Можно раскрыть **«Задать точку координатами»** и ввести широту/долготу WGS 84.
4. Выберите 500, 1000 или 2000 м и нажмите **«Исследовать»**. Публичный Overpass иногда отвечает долго или отказывает из-за нагрузки.
5. Категории включаются независимо; **«Показать все»** сбрасывает фильтры. Счётчики категорий показывают все найденные объекты, строка над списком — количество после фильтров.
6. Нажмите на объект в списке или на карте. Геометрия подсветится, появятся расстояние, направление, ссылка на OSM, основание классификации и раскрываемые исходные теги. Пунктир соединяет предприятие с ближайшей точкой выбранного объекта.
7. **JSON ↓ / CSV ↓** выгружают все объекты после текущих фильтров, включая ещё не раскрытые страницы списка. Список показывает по 100 строк, карта — всю отфильтрованную выборку.

Изменение точки или радиуса очищает прошлые результаты: повторите исследование. Изменение текста адреса само по себе не перемещает выбранную точку; текущие координаты и подпись всегда видны под картой.

## Произвольные адреса

Поле адреса при запуске пустое. Введите адрес нужного предприятия, выберите результат Nominatim и проверьте точку на карте. При отсутствии точного результата можно уточнить точку вручную или задать координаты WGS 84. Радиус по умолчанию — 2000 м. Поиск по кадастровому номеру доступен в Map First.

## Расчёты и геометрия

- Вход версии 0.1 — точка WGS 84. Для неё строится локальная азимутальная эквидистантная проекция **AEQD** на эллипсоиде WGS 84, единицы — метры, центр — исходная точка.
- Геометрии преобразуются через PyProj с `always_xy=True`. Shapely находит пару ближайших точек исходной и найденной геометрий. Расстояния в градусах и расстояния до центров объектов не используются.
- Направление определяется по вектору к ближайшей точке в этой метрической проекции. Север — 0°, отсчёт по часовой стрелке, восемь секторов по 45°; сектор С: [337,5°, 360°) ∪ [0°, 22,5°).
- Если исходная точка лежит внутри или на границе полигона, расстояние — 0, направление и азимут — `null` (в интерфейсе — «Пересечение»). Направление по центру такого объекта не придумывается.
- Поддерживаются nodes, ways (точки, линии, полигоны), relations multipolygon/boundary с внешними и внутренними кольцами. Незамкнутые ways сохраняются линиями. Явное `area=no` сохраняется. Некорректные полигоны исправляются `make_valid`, только если результат остаётся полигональным.
- Неполные геометрии и неподдерживаемые relations пропускаются с общим счётчиком и предупреждением, без замены центром. Вложенные relations не поддерживаются.
- Overpass получает геометрии в радиусе с запасом 25 м; локальный фильтр оставляет только расстояния **≤ выбранного радиуса** без округления. `is_in`/`pivot` дополнительно запрашивает содержащие точку территории `landuse`, `leisure`, `building`, границы которых могут быть далеко за кругом.
- Функция `MetricContext` принимает произвольную исходную геометрию и уже протестирована с полигоном. Для будущего входного полигона ещё потребуются интерфейс, API и изменение пространственного запроса Overpass. У полигонального источника направление будет относиться к паре ближайших точек.
- Ограничение широты интерфейса/API — ±85° для совместимости с веб-картой. Объекты, пересекающие антимеридиан, не обрабатываются специально.

## Классификация

Только детерминированные правила в `app/classification.py`; имена объектов не анализируются. Первое подходящее правило определяет основную категорию. Конкретные функции образования и медицины, отдых и АЗС проверяются до общих признаков промышленности, жилья, коммерции, инфраструктуры и зданий.

| Категория | Основные теги |
| --- | --- |
| Здания | `building=*`; для `building=yes` — «назначение не указано», неизвестное значение показывается буквально |
| Промышленность | `landuse=industrial`, `industrial=*`, `man_made=works`, `building=industrial/warehouse` |
| Жилая среда | `landuse=residential`, явные жилые значения `building` |
| Коммерция | `landuse=commercial/retail`, `shop=*`, `office=*`, коммерческие значения `building`, отдельные услуги `amenity` |
| Образование | `amenity=school/kindergarten/college/university/...`, образовательные здания, `landuse=education` |
| Медицина | `amenity=hospital/clinic/doctors/dentist/pharmacy/...`, `healthcare=*`, `building=hospital` |
| Отдых и озеленение | отдельные `leisure` (park, garden, playground, sports_centre и др.), `landuse=forest/recreation_ground/village_green` |
| АЗС | `amenity=fuel` |
| Инфраструктура | отдельные `power`, `man_made`, `amenity`, `highway`, `railway`, `public_transport` |

Точные списки значений находятся в таблице правил. Отрицательные значения `no/false/0` не классифицируются. Неизвестная функция не угадывается. Правила не охватывают все возможные схемы тегирования OSM. Один OSM-элемент получает одну основную категорию; исходные теги полностью сохраняются.

Объекты считаются по `node/way/relation + id`. Здание, предприятие-точка и территория могут описывать разные представления одного места — они не объединяются по смыслу. Это не число организаций или кадастровых участков.

## Экспорт

**JSON** — GeoJSON FeatureCollection, геометрия WGS 84, свойства с названием, типом, расстоянием без экранного округления, направлением, азимутом, ближайшей точкой, OSM ID, основанием классификации и исходными тегами. `metadata` содержит исходную точку, радиус, проекцию, время получения, срез OSM (если сервер сообщил), сведения о кеше, предупреждения, фильтры и количество экспортированных объектов.

**CSV** — UTF-8 с BOM, разделитель `;`, числа с десятичной точкой. Есть `tags_json`, `geometry_json`, параметры исходной точки и атрибуция. Потенциальные формулы в текстовых ячейках экранируются апострофом; JSON остаётся без такого преобразования. Для числовой обработки CSV при необходимости импортируйте с нужным десятичным разделителем.

Экспорт создаётся в браузере, не вызывает новых API-запросов и не сохраняет результаты на сервере. Кеш хранит только ответы внешних API.

## Публичные API и файловый кеш

Это инструмент для ручных локальных исследований. **Публичный Nominatim: максимум 1 запрос в секунду, без автодополнения и массового геокодирования.** Приложение сериализует запросы Nominatim, выдерживает минимум 1,1 с между их началами, передаёт идентифицирующий User-Agent и кеширует ответы. За соблюдение [политики Nominatim](https://operations.osmfoundation.org/policies/nominatim/) отвечает пользователь/разработчик этого локального приложения.

- Nominatim: `https://nominatim.openstreetmap.org/search`, TTL кеша **7 дней**.
- Overpass: `https://overpass-api.de/api/interpreter`, TTL **24 часа**; запросы сериализованы, интервал не менее 5 с. Таймаут выполнения запроса — 75 с, HTTP чтения — 100 с.
- HTTP 429 запускает паузу минимум 60 с, с учётом числового `Retry-After`. Автоматических повторов нет. Частичные ответы Overpass с `remark` отклоняются и не кешируются.
- Учитывайте [ограничения общих серверов Overpass](https://dev.overpass-api.de/overpass-doc/en/preface/commons.html). Доступность и полнота не гарантируются; для массового использования нужен собственный сервер или подходящий поставщик.
- Ключ файлового кеша — SHA-256 от URL и параметров. Файлы JSON записываются атомарно в `.cache/Nominatim` и `.cache/Overpass`. Повторный запрос в пределах TTL берёт ответ из файла; кеш работает после перезапуска. Истёкший кеш не выдаётся как свежий при ошибке сети.
- В интерфейсе видно время получения и использование кеша. Истёкшие файлы автоматически не удаляются: при необходимости очистите `.cache` при остановленном приложении. После очистки запросы снова пойдут в сеть.
- Leaflet 1.9.4 и его BSD-лицензия включены в `app/static/vendor`. CDN для запуска не требуется. Подложка загружается браузером с `tile.openstreetmap.org`, без предзагрузки/офлайн-скачивания; действует [политика OSM tiles](https://operations.osmfoundation.org/policies/tiles/). Браузер использует обычный HTTP-кеш тайлов. Подложка может быть недоступна независимо от API.

Перед запуском можно переопределить серверы и кеш через переменные окружения, без изменения кода:

```powershell
$env:NOMINATIM_URL = "https://nominatim.openstreetmap.org/search"
$env:OVERPASS_URL = "https://overpass-api.de/api/interpreter"
$env:OSM_USER_AGENT = "EcoburoGeo/0.1 (contact: YOUR_REAL_CONTACT)"
$env:CACHE_DIR = "C:\Project\ecoburo-geo\.cache"
.\start.ps1
```

Замените `YOUR_REAL_CONTACT` реальным контактом, если задаёте собственный User-Agent. При смене сервера проверьте его условия использования. Серверу Nominatim передаётся введённый адрес, Overpass — координаты и радиус, серверу тайлов — просматриваемая область. Приложение предназначено для публичных адресов предприятий. Не отправляйте конфиденциальные сведения в публичные API.

## Ограничения интерпретации

**OpenStreetMap не является официальным кадастровым источником. Классификация по OSM-тегам не устанавливает юридический вид разрешённого использования (ВРИ).** Это не санитарно-защитная зона и не оценка соблюдения нормативов.

Данные могут быть неполными, устаревшими, ошибочными и безымянными. Отсутствие элемента в выдаче не доказывает отсутствия объекта на местности. Overpass `is_in` зависит от обновления производных areas и не гарантирует нахождения всех крупных охватывающих полигонов. Направление у сложного объекта может быть неоднозначным, если ближайших точек несколько: используется одна из ближайших точек, выбранная Shapely.

## Тесты

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

Тесты не обращаются к интернету. Синтетические геометрии используются исключительно в тестах. Проверяются восемь направлений, границы секторов, метрические расстояния относительно независимого геодезического расчёта, ближайшие рёбра/линии, пересечение, отверстие полигона, будущий полигональный источник, разбор multipolygon, отсутствие классификации по имени, валидация API, ошибки, повторное использование кеша и пауза после 429.

Проверки переносимой Windows-версии описаны в [VERIFICATION_WINDOWS.md](VERIFICATION_WINDOWS.md).

## Структура

```text
app/
  main.py             # FastAPI, исследование, GeoJSON
  geo.py              # метрическая проекция и ближайшие точки
  osm.py              # геометрии Overpass
  classification.py   # категории и явные правила OSM-тегов
  services.py         # HTTP, лимиты, файловый кеш
  static/             # интерфейс и локальная копия Leaflet
tests/                # unittest, без сетевых запросов
requirements.txt
start.ps1
README.md
VERIFICATION_WINDOWS.md
```

API: `GET /api/geocode?q=...`, `POST /api/research` с JSON `{"lat": ..., "lon": ..., "radius": 2000}`, `GET /api/config`, `GET /api/health`. Интерактивная схема FastAPI — http://127.0.0.1:8000/docs. Сервер привязан к loopback и не предназначен для публикации в интернет.
